# Content Integrity

This document is for maintainers of this repository and for developers of clients that consume the published widget catalog. Widget developers do not need to do anything described here.

## Content hashes

The generated `build/manifests.json` catalog includes a SHA-512 `content_hash` for each widget, such as `sha512:0123...`. This value is generated by the builder and must _not_ be added to a widget's source `manifest.json`.

## Catalog signature

The publish workflow signs the exact bytes of `manifests.json` with Ed25519 and uploads the base64-encoded 64-byte signature as `manifests.json.sig`. Consumers must embed the corresponding public key, decode the signature from base64, and verify it before parsing or trusting the catalog. Do not reformat or re-encode the downloaded JSON before verification.

## Signing key setup

Repository administrators can create the signing key with OpenSSL:

```sh
openssl genpkey -algorithm Ed25519 -out manifest-signing-private.pem
openssl pkey -in manifest-signing-private.pem -pubout -out manifest-signing-public.pem
base64 --wrap=0 manifest-signing-private.pem
base64 --wrap=0 manifest-signing-public.pem
```

Store the private key's base64 output in the GitHub Actions repository secret `MANIFEST_SIGNING_PRIVATE_KEY_B64`. Store the public key's base64 output in the repository variable `MANIFEST_SIGNING_PUBLIC_KEY_B64`. CI verifies each signature against this separately configured public key, so a mismatched private key cannot publish an unusable catalog.

Embed `manifest-signing-public.pem` in the trusted game distribution. Never commit or publish the private key. Back it up securely: losing it requires shipping a game update with a new public key, while disclosure requires immediate key rotation.
